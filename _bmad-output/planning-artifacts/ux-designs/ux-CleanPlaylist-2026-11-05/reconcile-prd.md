### 1.2 Stitch AI Embellishments & Drift to Strip During Spine Distillation

Google Stitch generated high-craft layouts (`01`–`04`), but introduced hallucinated broadcast/AI chrome and minor token drift that **must be excluded** from `DESIGN.md` and `EXPERIENCE.md`:

1. **Strip Unrequested Header & Shell Chrome:**
   - Remove notification bell (`notifications`), settings gear (`settings`), help (`help_outline`), `"⌘K"` search bar, and user avatar/`"Curator Edu — Verified Staff"` (Screens 1, 3, 4).
   - Remove extra nav links (`Screening Rules`, `Export History`, `Workbench`, `Catalog`, `Replacements`) and Screen 3's background left sidebar (`Radio Station Library`, `Clean Swaps Index`, `Sensory Compliance`) and bottom audio transport player bar. Top navigation has **strictly 3 tabs**: `Scan & Clean`, `Keyword Search`, `Stitch Studio`.
2. **Strip Fake Broadcast, Bitrate & AI Confidence Telemetry:**
   - Remove `"Engine: Broadcast Audio Safe v2.4 • Latency: 14ms • Bitrate: 320 kbps (Lossless Match)"` (Screen 1), `"Zero radio infractions"` / `"Explicit vocal mutes verified"` / `"Matched to Radio Edit #104"` (Screen 2), `"Acoustic AI + Transcription Match"` / `"Policy: FCC Standard Section 14.2"` / `"Confidence: 99.4%"` / `"Snippet @ 01:22"` timecode (Screens 2 & 3), and `"Engine v4.2"` (Screen 4). Lyrics from YouTube Music are plain-text lines (`L01`–`Lnn`), not time-coded audio streams or ML confidence scores.
3. **Strip Deferred Playback & Share Widgets (`prd.md` §7.2):**
   - Remove Mobile Screen 2's `"Playback Engine: Radio Safe Stream"` interactive waveform scrub bar (`prd.md` §7.2 explicitly defers inline audio previews).
   - Remove inline hover play buttons (`play_arrow` in Screen 1 `#` column) and `"Headphone Preview"` buttons (`headphones` in Screen 4) — external `"Open Clean Track"` links and `"Play Clean Queue"` handle all listening.
   - Remove `"Share Link"` button in Screen 4 footer (`prd.md` §7.2 explicitly defers `#list=...` share links).
4. **Normalize Stitch Token & Control Drift Back to Locked Spec:**
   - **Icon Library (`AGENTS.md`, `NFR-4`):** Use `lucide-react` stroke icons in implementation, **not** Stitch's Google `Material Symbols Outlined` webfont.
   - **Pill Radius:** Restore standard Tailwind v4 `rounded-full` (`9999px`) for safety pills and preset chips (Stitch's inline Tailwind config overrode `full` to `0.75rem`).
   - **Safety Badge Color Consistency:** Screen 2 & Screen 4 drifted `Clean Swapped` to indigo/violet (`secondary`/`primary`), and Screen 1 drifted `Lyrics Unavailable` to indigo (`secondary`). Lock **`Verified Clean` and `Clean Swapped` to Emerald** (distinguished by `CheckCircle2` vs. `RefreshCw`/`ArrowLeftRight` icon + label) and lock **`Lyrics Unavailable` to Amber caution** (`#f59e0b` / `amber-400` on `amber-950/40` border `amber-500/40`) so missing lyrics visibly warn parents (`FR-6`, `NFR-3`, `SM-C1`).

   - **Stitch Studio Rule Options:** Replace Screen 4's invented dropdown labels (`"BPM Matched Flow"`, `"Teen Safe"`, `"Radio Edit Only"`) with the exact backend/PRD enums (see §2.2 & §4 below).

## 3. Brownfield `frontend/src/` Qualitative Affordances Audit

Inspection of `App.jsx`, `Navbar.jsx`, `ScanTab.jsx`, `KeywordsTab.jsx`, `StitchTab.jsx`, `LyricsModal.jsx`, `PlaylistPickerModal.jsx`, `SavePlaylistModal.jsx`, and `frontend/src/components/__tests__/` surfaced the following v1 UX affordances that **must be preserved (or cleanly evolved)** in the spines:

1. **Zero-Friction Empty-State Onboarding Samples (`ScanTab.jsx` L53–62, L304–319):**
   - *v1 behavior:* `"Try a sample: [Top Hits Sample] [Popular Pop]"` quick-load chips below the input bar.
   - *Public Launch evolution:* Keep quick-try sample chips inside the empty **Working List** / below the Smart Input Bar, adapted to `Active Platform` (e.g., on `spotify`: 1-click sample album search like *90s Hip-Hop Sample* or sample 5-song *Parent Test* paste; on `ytmusic`: 1-click public sample playlists) so first-time visitors can test scanning in one click without hunting for a URL.
2. **Working List Status Filter Pills, Inline Search & Dynamic Counters (`ScanTab.jsx` L244–261, L513–556; `ScanTab.test.jsx` L96–127):**
   - *v1 behavior:* Filter tabs (`All`, `Flagged`, `Clean`), inline `"Search tracks..."` filter input, and live header counters (`Flagged`, `Clean`, `Removed`) that update immediately when rows are deleted or swapped.
